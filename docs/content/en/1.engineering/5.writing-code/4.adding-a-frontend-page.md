---
title: "Adding a frontend page"
description: "The steps to add a page to the Nuxt app: its route, its components, its logic and its checks."
---

A page of the Nuxt app is a `.vue` file under `app/pages/`, whose path is its route: `app/pages/cellars/[id].vue`
answers `/cellars/42`. It composes components and makes the calls to the backend, and leaves the display to its
components and the logic to composables, where a test reaches them. Read this page before you add a page, along with
the [`frontend-feature` skill](https://github.com/mboisnard/drinkit/blob/master/.claude/skills/frontend-feature/SKILL.md),
which holds the rules an agent follows.

The page renders on the server first, then in the browser: what it does while it sets up runs twice, once without
`window`, as the [frontend architecture](../2.architecture/7.frontend-architecture.md) explains.

## 🛣️ Add the page

1. Write the test list first, as [test-driven development](https://github.com/mboisnard/drinkit/blob/master/.claude/skills/test-driven-development/SKILL.md)
   asks: what the user sees and does on the page.
2. Create `app/pages/<route>.vue` in kebab-case, `<template>` first, then `<script setup lang="ts">`.
3. Import every component it uses from `#components`, every Vue API from `vue` and every Nuxt composable from
   `#imports`: auto-imports are off.
4. Move what the page displays into components under `app/components/`, named in PascalCase and in two words at
   least, such as `CellarCard.vue`. A component takes props and emits events.
5. Move the logic and the state into a composable under `app/composables/`, named after it, such as `useCellars.ts`.
   State shared between components goes through `useState`, never a `ref` declared outside a function.
6. Call the backend through the client generated from the OpenAPI contract, never with a hand-written `fetch`. A
   call that needs a new operation changes the [contract](../2.architecture/5.contract-first.md) first.
7. Run the lint, the type check and the build of the app, with the commands of
   [`AGENTS.md`](https://github.com/mboisnard/drinkit/blob/master/AGENTS.md), then open the page in
   `pnpm --filter drinkit-frontend dev`.

The [frontend coding conventions](./1.best-practices/6.frontend-coding-conventions.md) give the reason of each rule the
lint applies on the way.

## 🚦 When the page fails

A route that matches no page, or an error a page throws with `showError`, renders the error page of `nuxt-starter`.
It shows the title and the detail of the ProblemDetail the error carries, so a page that catches an error of the
backend passes it on as the error's `data`.
